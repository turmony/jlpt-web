# 磁盘存储维护

源码目录与服务器发布版本的代码分别保留。仅复用安装版本及内容完全一致的依赖文件，不涉及 `jlpt-study`、课程版本或学习成果。

## 依赖共享

`scripts/share-dependencies.py` 使用逐文件硬链接，保留两处独立的真实目录及原有符号链接。脚本先核对 lockfile、所有源码依赖文件的内容与权限，再原子替换相同文件的目录项。默认只预览：

```bash
python3 scripts/share-dependencies.py
python3 scripts/share-dependencies.py --apply
```

默认部署目录为 `/srv/jlpt/app`；其他位置通过 `--deployed` 指定。两处依赖必须位于同一文件系统；共享期间不要同时安装、升级或修改任一处依赖。不同版本、文件内容或权限不一致时拒绝共享。

不要将源码的整个 `node_modules` 符号链接到生产依赖：实测 `npm ci` 会清空链接目标。逐文件硬链接允许源码重装时独立删除目录项，部署文件继续保留。修改依赖应先执行 `npm ci`，不要直接编辑共享文件，也不要执行会原地修改它们的补丁或升级命令。部署安装脚本会先解除发布版本的 `node_modules` 目录链接，再执行重装，保护其他回滚版本。

依赖重装后，可在两处版本完全一致时再次执行共享命令。构建产物、认证文件、SQLite 和学习成果不参与此共享。

## 构建资源

`npm run build` 的本地 `server-public` 通过文件硬链接复用 `chat/dist` 中的 JS、CSS 和字体，省去一份聊天资源，同时兼容应用禁止符号链接的静态文件路径检查。两个目录都属于可重建产物，不进入 Git。

指定外部目录时仍复制独立文件：

```bash
node scripts/build-server.mjs /绝对路径/新发布版本/static
```

后续本地构建不会改变已发布文件或回滚版本。发布应使用上述命令构建独立目录。课程图片继续由发布准备脚本通过硬链接复用；重复安装时先校验图片内容，相同内容保留共享文件，需要更新时写入临时文件后原子替换，避免原地重写损坏回滚图片。

## 发布与备份保留

只保留 `/srv/jlpt/app`、`/srv/jlpt/static` 当前指向的发布版本，以及当前版本 `previous-release.txt` 指定的上一版本。删除旧发布前，核对它们不再承载应用、静态资源或独有的学习数据。硬链接图片的表观大小不能直接累加为可回收空间。

旧清理备份可以在确认不再需要回滚到那些版本后移除。长期保留 `/srv/jlpt/state`、资料库及学习 worktree；本次优化未删除这些目录。后续新增发布或备份仍需按此规则维护，脚本不会自动删除历史版本。
