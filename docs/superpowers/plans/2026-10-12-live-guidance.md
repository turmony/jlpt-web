# Codex 运行中直接接收新消息

用户确认的动作顺序：第一条消息启动 Codex；运行期间用户编辑并发送第二条消息；网页立即通过当前连接和会话传入；Codex 接收并调整后续执行；页面继续显示工具与文字。仅 Codex 启用，其他 CLI 不上线该功能。不停止、重启或另开一轮，也不安排下一轮排队。

实现：
- SendBox 在运行中且 Codex 已就绪时允许发送，有文本显示发送按钮，空白显示停止。
- 认证 POST /api/tasks/:id/input 原样发送文本，使用请求编号避免网络重试重复送达。记录用户消息及送达回执，不改当前模型和轮次。
- Worker 通过正在运行的 Python CLI/Node stdin 连接立即转交，ACP 使用 _session/steering 进入当前 turn；实际确认注入后 HTTP 返回成功。
- 版本校验的 activeOnly 兼容补丁防止轮次结束竞争触发新一轮。尚未就绪或已经结束则明确拒绝，保留草稿。不支持的 CLI 仍使用原发送流程。
- 检查流式与历史消息去重、新草稿与会话切换、取消、重启和送达竞争，再在隔离目录验证真实 Codex 工具运行期间接收补充消息，最后发布。

分工：ACP runner、兼容补丁及协议测试与前端交互及浏览器测试独立实现；主任务实现 Store、Worker、HTTP、Python CLI 协调和真实验证。送达状态为 sending、delivered、failed；没有自动下一轮执行。
