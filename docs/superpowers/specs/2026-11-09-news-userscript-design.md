# 新闻阅读改为用户脚本：设计

记录日期：2026-11-09。

本文整理与用户逐段确认的需求与设计，是后续实现的依据。写入本文不代表功能已经完成。本文取代 `2026-11-08-news-reader-design.md` 中「获取新闻的方式」「新闻列表页」「阅读页」「抓取」「存储（文章与图片）」及相关接口的内容；查词、句子分析、连续追问、模型选择和提示词的设计沿用原文，本文只写变化。

## 1. 目标与范围

原设计由服务器抓取雅虎新闻，在本站自己的阅读页重新排版显示。用户认为这不符合预期：希望看到的是新闻网站的原版排版和内容，并在上面查词、分析句子。

新的做法：用户在 Safari 里直接打开雅虎新闻的文章页，由 Safari 扩展 Userscripts 运行本站提供的脚本，在原页面上加入查词卡、长按选句、分析面板、连续追问、模型选择和分环节报错。

已确认的范围：

- 第一版只支持雅虎新闻文章页（`https://news.yahoo.co.jp/articles/…`）；以后加网站时，每个网站加一行配置。
- 本站的 `/news/`（列表页和阅读页）直接删除，不保留、不做说明页；另设一个很小的「新闻脚本」管理页 `/news-script/`，只用于安装脚本和按设备作废令牌（第 3 节）。
- 查词、句子分析、追问的内容与规则沿用原设计；查词与分析记录、追问对话仍不保存。

第一版不做：振假名、字号调整、生词本、阅读进度保存、雅虎以外的网站。

## 2. 选择这种做法的依据

### 考虑过的做法

| 做法 | 结论 |
|---|---|
| 服务器提取正文，本站统一排版（原设计） | 稳定，但不是原版排版，用户不接受 |
| 服务器用 monolith 保存整个网页，去掉脚本后在本站显示 | 接近原版；但正文靠脚本加载的网站会空白，资源下载要另做内网访问防护，维护面较大 |
| 把原网页放进沙盒 iframe，由外层页面加事件 | Safari 在沙盒 iframe 没有 `allow-scripts` 时会拦截外层加的事件（WebKit bug 218086、209653），不可行 |
| 在原网页上运行用户脚本（本文采用） | 排版与原版完全一致；服务器不抓网页、不存图片；需要在设备上安装 Userscripts 扩展 |

### 实测（2026-11-09，一次性试验，代码未进仓库）

在服务器上用 Playwright WebKit 模拟 iPhone 15 与 iPad Pro 11 横屏，打开 3 个分类的真实雅虎文章，注入模拟用户脚本，连接本机 HTTPS 测试服务：

- 雅虎文章页没有 CSP（响应头与页面 meta 均无），页面内可以直接 `fetch` 本站接口；只有 `x-frame-options: DENY`，与本做法无关。
- 正文由服务器直接输出在 HTML 中：`article#uamods .article_body`；iPhone 版正文完整，没有「続きを読む」折叠。iPad 收到的是宽 1010 的电脑版页面（Safari 在 iPad 上默认按电脑版访问）。
- 带令牌的跨域请求（CORS 预检 + `Authorization` 头）正常；流式返回逐段到达，约 0.6 秒一段，页面刚加载、较忙时开头几段会合并到达。
- 在 React 水合之前包词，iPhone 上 React 报错（#418、#423）并重新渲染 `MAIN`，词标记全部丢失；等页面 `load` 后再包词，没有报错，滚动 20 多秒后词标记都还在；提前包词时加上「被清掉后自动重包」，一帧之内全部恢复。
- 点词能弹出 Shadow DOM 中的查词卡，不会误触链接跳转，雅虎的触摸事件没有阻止默认行为。iPad 上第一次点词失败，原因是测试工具的坐标没有按页面缩放（约 1.18 倍）换算，换算后正常。
- 未验证：长按与拖选（模拟器做不了长按）、雅虎多页文章翻页是整页刷新还是页面内切换、Userscripts 在用户 iOS 版本上的实际表现。这些在实现与上线前检查中确认。

## 3. 整体结构

```
Safari 打开雅虎文章
  └ Userscripts 扩展运行「加载器」（几行代码，含令牌）
       └ 从本站取「主脚本」并运行
            ├ 等页面 load 完成，找到标题与正文
            ├ 把各段文字发给本站分词，再包上词标记（被页面清掉时自动重包）
            └ 在 Shadow DOM 里加查词卡、分析面板、右下角按钮
本站服务器：分词、查词、分析、追问、模型列表（令牌验证，允许雅虎跨域调用）
```

### 安装：加载器与主脚本

- **加载器**每台设备装一次。用户登录本站后，在这台设备的 Safari 里打开「新闻脚本」管理页，填写设备名称（按 User-Agent 预填「iPad」或「iPhone」），点「安装到这台设备」，即打开 `/api/news/install/<设备名称>/jlpt-news.user.js`：服务器为这台设备生成令牌，返回一份写好令牌的 `.user.js`，Userscripts 弹出安装提示，点安装即可，不需要手动粘贴令牌。加载器的 `@match` 列出支持的网站。
- **主脚本**由加载器每次用令牌从本站取最新版（`GET /api/news/client.js`）后运行。主脚本用 esbuild（仓库已有）打包成一个文件。上线更新后设备上不必重装。
- 站点导航中的「新闻」改为「新闻脚本」，指向管理页。

### 新闻脚本管理页 `/news-script/`

需要登录，与其他页面一样走现有的登录检查。页面只有两块：

- 安装：设备名称输入框和「安装到这台设备」按钮，下面一句说明「需要先在 App Store 安装 Userscripts 并在 Safari 中启用」。
- 设备列表：每台设备一行，显示名称、安装时间、最近使用时间和「作废」按钮。作废后这台设备上的脚本立即失效，提示重新安装。

### 令牌

- 每台设备一个令牌。服务器生成随机令牌，`state/news/devices.json` 只保存设备编号、名称、令牌散列值、安装时间、最近使用时间。
- 新闻接口同时接受登录 Cookie 或 `Authorization: Bearer <令牌>`。
- 用同一个设备名称再次安装时，替换这个名称原来的令牌（旧令牌立即失效），避免重复安装后设备越积越多。不同名称的设备互不影响。
- 设备最多 10 台；已满时安装报错，提示先作废不用的设备。
- 最近使用时间在令牌被使用时更新，最多每 10 分钟写一次文件。
- 脚本泄露时，在管理页作废那台设备，或用同一名称重装。

### 跨域

- 只对允许列表中的来源开放 CORS，第一版为 `https://news.yahoo.co.jp`；列表放在服务器配置中，以后加网站时追加。
- 处理 `OPTIONS` 预检请求。
- 现有「POST 必须同源」的检查保留；只对「带有效令牌且来源在允许列表中」的请求放行。只带 Cookie 的外站 POST 照旧被拒。

### 网站表

主脚本里每个网站一行，第一版只有：

```js
{match: 'news.yahoo.co.jp/articles/', parts: ['h1', '.article_body']}
```

加网站时：主脚本网站表、加载器 `@match`、服务器 CORS 允许列表各加一项。

## 4. 删除与保留

删除：

- 服务器：`server/news_yahoo.py`（RSS、话题页、多页抓取）；文章与图片的保存、补抓与过期清理；`/api/news/feeds`、`/api/news/open`、`/api/news/image/…`；抽查脚本 `scripts/news_probe.py`。
- 网页：`web/news/` 整个目录；导航中的旧链接（`scripts/build-server.mjs`、`web/papers.html`）改为指向新增的管理页 `web/news-script/`。
- 测试：雅虎样例（`tests/server/news_fixtures/`）及抓取、文章存储相关测试。

保留：释义缓存 `state/news/glossary.sqlite`（30 天）、模型设置 `state/news/settings.json`、分词（`news_text.py`）、模型调用（`llm.py`）、提示词与回复解析（`news_prompts.py`、`news_xml.py`）、错误结构（`news_errors.py`）。原阅读页中的查词卡、分析面板、页头选模型等前端代码改造后移入主脚本。

## 5. 接口

所有新闻接口要求登录 Cookie 或有效令牌；POST 的同源规则见第 3 节「跨域」。

| 接口 | 用途 | 变化 |
|---|---|---|
| `GET /api/news/install/<设备名称>/jlpt-news.user.js` | 为这台设备生成令牌，返回写好令牌的加载器 | 新增；只接受登录 Cookie；名称 1–20 字 |
| `GET /api/news/devices` | 设备列表（不含令牌） | 新增；只接受登录 Cookie |
| `POST /api/news/devices/revoke` `{id}` | 作废一台设备 | 新增；只接受登录 Cookie，须同源 |
| `GET /api/news/client.js` | 主脚本 | 新增；需令牌 |
| `POST /api/news/tokenize` `{paragraphs: [文字…]}` | 每段的句子与词（原文、读音、词典形、词性、是否可点） | 新增；一次最多 200 段、共 2 万字 |
| `POST /api/news/gloss` `{lemma, reading, pos}` | 词语释义 | 不变 |
| `POST /api/news/analyze` `{paragraph, tokens, start, end}` | 句子分析，流式 | 原按服务器存的文章与句子编号取句子，改为由脚本直接发送所在段落文字与这句的词列表 |
| `POST /api/news/ask` `{paragraph, tokens, start, end, history, question}` | 追问，流式 | 同上 |
| `GET /api/news/models`、`POST /api/news/settings` | 模型列表与所选模型 | 不变 |

`start`、`end` 仍是选中部分在句中的词序号，不选部分时为空。服务器检查选中范围不越界、段落与句子长度不超限。

## 6. 页面上的操作与界面

### 可以点的范围

- 只有标题（`h1`）与正文（`.article_body`，含图片说明）里的文字可以点，其余保持雅虎原样。
- 只对这两块关闭系统长按选字菜单（`-webkit-user-select: none`、`-webkit-touch-callout: none`），页面其他地方照常能选字。
- 正文里的关键词链接、图片说明链接上点词时查词，不跳转；点链接旁空白或图片本身仍按原链接打开。

### 操作

| 动作 | 结果 |
|---|---|
| 点一个词 | 在词旁弹出查词卡（读音、🔊、词性、中文释义、「在本句中的作用」）；点别处关闭 |
| 长按句子 | 选中整句（底色高亮），打开分析面板 |
| 在已选中的句子上拖选 | 选区对齐到整词，分析改为针对选中部分 |
| 长按另一句 | 换句，追问清空 |

- 快速连点只查最后一个词；标点、数字不可点。
- 只有在已选中的句子上拖动才是选择，其他地方拖动照常滚动页面。

### 分析面板与连续追问

- 内容和规则与原设计相同：原文、选中部分、译文、语法（可展开）、语法卡链接、追问。
- 语法卡链接改为本站 `/grammar/` 的完整地址，在新标签页打开。
- iPad 横屏：面板浮在右侧约 35% 宽，盖住雅虎右侧栏，左边正文照常滚动、点词。
- iPad 竖屏与 iPhone：从底部弹出，可上拉到全屏，下拉关闭。
- 查词卡与面板放在 Shadow DOM 中；句子高亮用加入页面的一小段样式。

### 右下角按钮

页面上没有本站页头，原页头的功能改由右下角一个小圆按钮承担：

- 平时显示状态：「分词中…」「就绪」「出错」。
- 点开：「模型：××」（点开是 qoder2api-hub 当前可用模型）、「重新分词」、出错时的报错一行（可展开完整信息）。
- 所选模型下线时提示「当前模型不可用，请重新选择」，不自动换用其他模型。

### 包词的时机、重包与翻页

- 页面一加载就请求分词（不改页面）；等 `load` 事件后再把词标记包到原文字上。
- 分词结果按段落文字缓存。监听页面变化，词标记被清掉时按缓存自动重包。
- 雅虎多页文章翻页：整页刷新时脚本重新运行；页面内切换时，发现正文出现新文字，对没缓存的段落补发分词请求。
- 一个词被链接、加粗等行内元素切开时，词标记在边界处分成几段，同属一个词。

## 7. 分环节的出错处理

### 链路与环节

- 打开文章：① 加载主脚本 → ② 找到正文 → ③ 脚本→服务器 → ④ 切句分词 → ⑤ 标出词
- 查词、句子分析、追问：① 脚本→服务器 → ② 服务器→qoder2api-hub → ③ 模型生成 → ④ 解析回复 → ⑤ 推送到网页
- 删除原设计中的「抓取雅虎」「解析正文」「下载图片」环节，以及新闻列表的链路。

| 新环节 | 判定边界 | 处理 |
|---|---|---|
| 加载主脚本 | 加载器取不到主脚本（断网、令牌无效） | 加载器自己在右下角显示红色小按钮，点开看原因 |
| 找到正文 | 页面上找不到网站表里的选择器，多半是网站改版 | 报错并注明找不到的选择器；不能重试 |
| 脚本→服务器 | 请求没有到达服务器，或回应不是约定格式 | 返回 401 时提示「令牌已失效，请重新安装脚本」，附安装地址 |
| 标出词 | 分词结果与原文对不上 | 只跳过这一段并注明第几段，其余段落照常可点 |

### 沿用的规则

- 统一错误结构：环节、位置、原因、能否重试、请求编号、时间；请求编号写入服务器日志。日志不记录令牌、Cookie 和 API Key。
- 报错只显示一行，点开显示完整信息；已拿到的内容照常显示。
- 打开文章时的错误显示在右下角按钮中；查词的错误在查词卡中；分析与追问的错误在面板中出问题的位置。
- 30 秒无输出或总时长超过 2 分钟算超时；模型请求最多同时 3 个；换句或关闭面板时取消正在生成的回答，服务器同时停止读取上游。
- 回复格式不完整时，能解析的部分照常显示，其余放在「其他内容」下。

## 8. 测试

### 服务端（Python `unittest`）

- 分词接口：每段的句子与词正确，引号内不切句；超过 200 段或 2 万字时报错。
- 令牌：有效令牌可用、错误令牌被拒；服务器只存散列值；两台设备的令牌同时可用；作废一台后只有它失效；同名重装后该名称的旧令牌失效、其他设备不受影响；满 10 台时安装报错；最近使用时间按 10 分钟间隔更新。
- 跨域：允许的来源得到 CORS 头、预检正常；不在列表中的来源得不到 CORS 头，POST 被拒；只带 Cookie 的外站 POST 照旧被拒。
- 安装、设备列表与作废：未登录被拒，只带令牌也被拒（令牌不能管理设备）；设备名称为空或超过 20 字报错；返回的 `.user.js` 写有令牌，`@match` 正确；设备列表不含令牌或散列值。主脚本地址没有令牌被拒。
- 分析与追问：由脚本直接发送句子后，选中范围越界、文字过长时报错。
- 删除雅虎抓取、文章与图片存储相关测试。

### 浏览器测试（Playwright WebKit，模拟 iPad 与 iPhone）

- 仿雅虎结构的样例页面放在另一个本机端口，作为跨域来源；样例页面中有一段脚本在 1 秒后整块重新渲染正文，模拟 React 重渲染。
- 管理页：按 User-Agent 预填设备名称；作废后列表更新。
- 检查：`load` 后包词、被清掉后自动重包；点词弹卡、快速连点只显示最后一个；点链接里的词不跳转；长按选句、拖选对齐整词；iPad 横屏面板在右、竖屏与 iPhone 从底部弹出；换句后追问清空；右下角按钮切换模型；令牌失效时提示重新安装；分析流式逐段到达。
- iPad 上点击坐标须按页面缩放换算。

### 真实雅虎抽查脚本（取代 `scripts/news_probe.py`，手动运行）

用 WebKit 打开当天各分类雅虎文章，注入真实主脚本并连接本机服务，逐篇报告：是否找到正文、标出多少词、是否发生重包、有无报错。上线前运行一次；怀疑雅虎改版时随时运行。

### 真实模型测试

保留原有一组，只把请求改为新格式。

### 上线前人工检查

在用户的 iPad 与 iPhone 上安装 Userscripts 与加载器，实际操作点词、长按、拖选与面板，并确认多页文章翻页时的表现。

## 9. 部署

- 上线时一次性删除 `state/news/` 下旧的文章与图片目录，保留 `glossary.sqlite`、`settings.json`（新增的 `devices.json` 同样保留）。
- Caddy 不需要修改：`/api/*` 直接转给服务，`OPTIONS` 预检也会转过去；流式接口已关闭缓冲。
- 回滚方式沿用 20261108-news 的记录。
