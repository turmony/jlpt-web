# 新闻阅读：查词与句子分析设计

记录日期：2026-11-08。

本文整理与用户逐段确认的需求与设计，是后续实现的依据。写入本文不代表功能已经完成。

## 1. 目标与范围

在 JLPT 网站上增加看新闻的入口，主要在 iPad 和 iPhone 的 Safari 上使用。阅读时遇到生词能马上查到读音和简明释义；遇到看不懂的句子，能看到选中部分在句中的作用、整句的意思和涉及的语法，并可以围绕这个句子连续追问。

已确认的范围：

- 新闻来源：第一版只做雅虎新闻；朝日新闻以后再加，后端按来源分模块，以便新增。
- 查词：假名读音、iPad 自带的日语朗读、中文简明释义。
- 句子分析：N5 到 N1 的语法都讲，不按用户当前的备考等级筛选。
- 查词与分析记录不保存；追问对话也不保存。
- 查词、句子分析和追问使用同一个模型，由用户在页面上手动选择。

第一版不做：振假名、字号调整、生词本、阅读进度保存、Safari 分享快捷指令。

## 2. 获取新闻的方式

雅虎新闻页面返回 `x-frame-options: DENY`，不能嵌入；跨域时网页也读不到用户选中的文字。因此由服务器抓取正文，在本站自己的阅读页显示。

2026-11-08 在服务器上的实测结论：

- RSS 可用：`https://news.yahoo.co.jp/rss/topics/<分类>.xml`，提供标题、话题链接（`/pickup/<编号>`）和时间。
- 话题页的 `window.__PRELOADED_STATE__` 中，`topicsDetail.article.url` 是文章链接（`/articles/<ID>`）。
- 文章页的 `__PRELOADED_STATE__.articleDetail` 提供结构化正文：`headline`、`media.mediaName`、`createDateTime`、`author`、`paragraphs`（每段含 `head` 小标题、`textDetails` 文字、`objectItems` 图片及说明）、`richBody`（元素树）、`currentPage` / `maxPage`。
- 抽查 8 个分类共 24 篇：全部能解析；6 篇分 2–5 页，每页只含当页内容，需逐页抓 `?page=N`；1 篇带雅虎视频播放器（`richBody` 中的 `yjrf-yvp`）。
- 图片地址带约 3 小时的过期参数（`exp=10800`），必须在打开文章时由服务器保存。
- robots.txt 对普通访问不限制文章页，只全站屏蔽 AI 爬虫及评论、API 路径。本功能只在用户打开文章时按需抓取，不批量爬取；新闻版权归原媒体，网站只在有密码的站点上自用。

## 3. 页面与操作

### 入口

站点导航加入「新闻」，进入 `/news/`。

### 页头

列表页和阅读页的页头右侧显示「模型：××」，点一下弹出 qoder2api-hub 当前可用的模型列表，选择后即生效。

### 新闻列表页 `/news/`

- 顶部是分类：主要、国内、国际、经济、娱乐、体育、IT、科学。
- 下面是标题和时间，点标题进入阅读页。
- 底部可以粘贴雅虎新闻链接，打开不在列表里的文章。

### 阅读页

- 显示标题、媒体、时间、原文链接，以及小标题、段落、图片和图片说明。
- 多页文章合成一篇连续显示。
- 视频显示封面和「在雅虎观看」。
- 认不出的内容在原位置显示「这里有原文内容没能显示」。
- 图片说明也可以点词查询。
- 关闭系统自带的长按选字菜单（`-webkit-user-select: none`、`-webkit-touch-callout: none`）。

### 操作

| 动作 | 结果 |
|---|---|
| 点一个词 | 在词旁边弹出查词卡；点别处关闭 |
| 长按句中任意位置 | 选中整句（底色高亮），打开分析面板 |
| 在已选中的句子上拖过几个词 | 选区对齐到整词，分析改为针对选中部分 |
| 查词卡上的「在本句中的作用」 | 以这个词作为选中部分进行分析 |
| 长按另一个句子 | 换句，追问清空 |

- 标点和数字不可点；助词、助动词可以点，与其他词一样由模型给出释义。
- 只有在已选中的句子上拖动才是选择，其他地方拖动照常滚动页面。
- 快速连续点不同的词时，只请求最后一个词。

### 查词卡

```
勢力  せいりょく  🔊
名词
势力；力量，强度
在本句中的作用
```

朗读使用 `speechSynthesis` 的日语语音，不经过服务器。

### 分析面板

- iPad 横屏时占右侧约 40%，左边文章可以继续滚动、点词。
- iPad 竖屏和 iPhone 上从底部弹出，可以上拉到全屏，下拉关闭。
- 面板内不放朗读按钮和快捷追问按钮，不使用装饰性分隔符号。

只选整句时：

```
原文
台風32号は強い勢力で、10日(火)から11日(水)にかけて
小笠原諸島に接近するおそれがあります。

译文
台风32号可能会以强劲的势力，在10日（周二）至11日
（周三）期间接近小笠原诸岛。

语法
〜は            N5  提示主题
〜で            N5  表示状态、方式
〜から〜にかけて  N3  从…到…期间
〜おそれがある    N2  有…的可能（多指坏事）

想问什么…
```

选中句中一部分时，原文中的选中部分以底色高亮，并在译文上方多出一块：

```
強い勢力で  つよいせいりょくで
修饰「接近する」，说明台风以什么状态接近。
で 表示状态，不是地点。
本句中：以强劲的势力
```

- 语法每条一行（形式、等级、一句话说明），点一下展开接续、本句用法、易混淆形式。
- 只选整句时，语法按在句中出现的顺序排列；选中部分时，相关语法排在最前。
- 语法形式能在语法卡目录中找到时，这一条旁边显示语法卡链接。

### 连续追问

```
追问
我：可以换成「強い勢力に」吗？
答：不行。に 会变成「变成强劲势力」的意思……

想问什么…
```

| 情况 | 处理 |
|---|---|
| 同一句里继续提问 | 接着之前的对话 |
| 同一句里改选另一部分 | 分析换成新选中的部分，对话保留 |
| 换到另一个句子 | 对话清空 |
| 关掉面板或离开文章 | 对话不保存 |
| 对话很长 | 只把最近 6 轮问答发给模型；原句和分析结果始终发送 |

追问只用「我」「答」区分，不用气泡或头像。

## 4. 后端

### 模块

| 文件 | 职责 |
|---|---|
| `server/news.py` | 新闻接口的路由、登录与同源检查 |
| `server/news_yahoo.py` | RSS、话题页到文章页、逐页抓取、整理成统一结构 |
| `server/news_text.py` | 切句、分词，得到词典形、读音、词性 |
| `server/news_store.py` | 文章、图片、释义缓存和设置的读写与过期清理 |
| `server/llm.py` | 调用本机 qoder2api-hub，逐段读取流式结果 |

新增来源（如朝日新闻）时新增 `news_<来源>.py`，输出同样的文章结构，其余模块不变。

### 抓取

- RSS 每个分类缓存 10 分钟。
- 打开文章：话题链接先换成文章链接；抓第 1 页，读出 `maxPage`，依次抓其余各页，每页间隔约 0.5 秒；单次请求超时 10 秒。
- 正文取自 `articleDetail.paragraphs`；同时遍历 `richBody`，对视频播放器和不认识的元素在对应位置放提示。
- 只接受 `https://news.yahoo.co.jp/pickup/…` 和 `https://news.yahoo.co.jp/articles/…`；不跟随跳转到其他主机。
- 同一篇文章同时被打开两次时只抓一次。

### 切句与分词

- 按「。！？」和换行切句；引号「」内不切。
- 使用 fugashi + unidic-lite 分词，每个词记录原文、读音（平假名）、词典形、词性、是否可点（标点和数字不可点）。
- 依赖安装在独立的 Python 环境 `/srv/jlpt/venv`，`jlpt.service` 改用该环境启动；部署脚本相应调整。
- 服务器内存约 1.9 GB、可用约 490 MB（2026-11-08）。实现前先测分词工具实际的内存与磁盘占用，再确定词典版本。
- 分词组件缺失时只有新闻功能报错，登录、语法、复习和试卷不受影响。

### 存储

| 内容 | 位置 | 保留 |
|---|---|---|
| 整理后的文章 | `state/news/<文章ID>/article.json` | 7 天 |
| 图片 | `state/news/<文章ID>/images/` | 7 天；打开文章时下载，单张上限 5 MB |
| 释义缓存 | `state/news/glossary.sqlite`，键为「模型名 + 词典形 + 词性」 | 30 天 |
| 模型设置 | `state/news/settings.json` | 长期 |

- 服务启动时及之后每小时清理过期内容；新闻目录总上限 300 MB，超出时先删最早的文章。
- 查词与分析记录不保存；追问对话只在页面上，每次随请求发送，服务器不留存。

### 接口

所有接口要求已登录；POST 请求要求同源。

| 接口 | 用途 |
|---|---|
| `GET /api/news/feeds?cat=<分类>` | 标题列表 |
| `POST /api/news/open` `{url}` | 打开文章，返回已切句、分词的整篇文章 |
| `GET /api/news/image/<文章ID>/<序号>` | 已保存的图片 |
| `GET /api/news/models`、`POST /api/news/settings` `{model}` | 可用模型列表；保存所选模型 |
| `POST /api/news/gloss` `{lemma, reading, pos}` | 词语中文释义（先查缓存） |
| `POST /api/news/analyze` `{article, sentence, start, end}` | 句子分析，流式返回 |
| `POST /api/news/ask` `{article, sentence, start, end, history, question}` | 追问，流式返回 |

`start`、`end` 是选中部分在句中的词序号，不选部分时为空。流式接口使用 Server-Sent Events。

### 配置

服务器配置文件新增 `llm`：qoder2api-hub 的本机地址（`http://127.0.0.1:8790`）和 API Key。模型名不写在配置里，由页头设置决定。Caddy 对 `/api/news/analyze` 和 `/api/news/ask` 关闭响应缓冲。

## 5. 大模型

### 模型

查词、句子分析和追问都使用页头选定的同一个模型，思考档位设低。所选模型被关闭或下线时提示「当前模型不可用，请重新选择」，不自动换用其他模型。

### 提示词原则

提示词里只放带说明的模板，不放填好具体句子的示例，避免模型照抄示例的措辞或内容。所有回答使用中文。

### 查词释义

发送词典形、读音、词性。回复模板：

```xml
<gloss>
  <meaning>中文释义。最多两个义项，用「；」分隔，每个义项不超过 15 个字。
    助词、助动词写出它的主要功能。</meaning>
</gloss>
```

### 句子分析

发送所在段落、原句、选中部分（如有）。回复模板：

```xml
<analysis>
  <selection>
    <reading>选中部分的平假名读音</reading>
    <role>选中部分在句中的作用：修饰或说明哪个成分、起什么作用</role>
    <meaning>选中部分在本句中的中文意思</meaning>
  </selection>
  <translation>整句的通顺中文译文</translation>
  <grammar>
    <item related="true 或 false">
      <form>语法形式，例如 〜ている</form>
      <level>N5、N4、N3、N2、N1 之一</level>
      <brief>一句话说明功能，不超过 15 个字</brief>
      <connection>接续方式</connection>
      <usage>在本句中的具体用法和意思</usage>
      <confusable>容易混淆的形式及区别；没有就省略这个标签</confusable>
    </item>
  </grammar>
</analysis>
```

规则：没有选中部分时不输出 `<selection>`；语法覆盖 N5 到 N1，按在句中出现的顺序排列；与选中部分相关的标 `related="true"` 并排在最前；标签之外不写任何内容。

服务器边接收边解析（增量 XML 解析）。`<selection>`、`<translation>` 和每个 `<item>` 一结束就作为一个事件推送给页面。

### 连到语法卡

把 `<form>` 和语法卡目录 `data/catalog.json` 中卡片 `title` 的「：」之前部分比较。两边都去掉「～」「〜」和空格，并按「／」拆开多个形式，完全一致才算命中；命中时显示指向 `/grammar/` 对应卡片的链接，不做模糊匹配。

### 追问

发送原句、选中部分、分析结果、最近 6 轮问答和新问题。回答为普通中文文字，不套模板；要求简短，能举例时给一个对比例句。

## 6. 分环节的出错处理

### 链路与环节

- 打开文章：① 网页→服务器 → ② 抓取雅虎 → ③ 解析正文 → ④ 切句分词 → ⑤ 下载图片 → ⑥ 返回网页
- 查词、句子分析、追问：① 网页→服务器 → ② 服务器→qoder2api-hub → ③ 模型生成 → ④ 解析回复 → ⑤ 推送到网页
- 新闻列表：① 网页→服务器 → ② 抓取雅虎 RSS → ③ 解析列表

| 环节 | 判定边界 | 常见错误 |
|---|---|---|
| 网页→服务器 | 没有收到服务器回应，或回应不是约定格式 | 网络断开、登录过期、服务未运行 |
| 抓取雅虎 | 服务器请求雅虎失败（注明第几页、哪个地址） | 超时、404 下架、403 拒绝 |
| 解析正文 | 页面已取得，但找不到正文数据 | 雅虎改版 |
| 切句分词 | 分词工具报错 | 组件未安装、异常字符 |
| 下载图片 | 某张图片失败（注明第几张） | 超时、超过 5 MB、已过期 |
| 服务器→qoder2api-hub | 连不上或它直接返回错误 | 服务未运行、API Key 错误 |
| 模型生成 | 已连上，模型方面出错；30 秒无任何输出也归此环节 | 排队（10605）、模型下线、额度不足 |
| 解析回复 | 模型已回答，格式不符合模板 | 标签缺失或写错 |
| 推送到网页 | 回答已开始显示，中途断开 | 网络切换、锁屏 |

### 错误信息

服务器生成统一结构；「网页→服务器」由网页自己生成：

```
环节       抓取雅虎
位置       第 3 页 / 共 3 页
原因       雅虎返回 503，服务暂时不可用
能否重试   能
请求编号   n-20261108-a3f9
时间       15:42:07
```

请求编号同时写入服务器日志，用于定位。日志不记录密码、Cookie 和 API Key。

### 显示

- 报错时只显示一行，例如「抓取雅虎失败（第 3 页）：雅虎返回 503　重试」，点开显示完整信息。
- 已拿到的内容照常显示（如前两页正文、已生成的译文），报错行出现在出问题的位置。
- 等待时显示当前环节，例如「正在抓取雅虎（第 2 / 3 页）…」「正在分词…」「等待模型回应…」。
- RSS 获取失败但有旧缓存时，显示旧列表并注明「更新失败，显示的是 X 分钟前的列表」。
- 回复格式不完整时，能解析的部分照常显示，其余原样放在最后的「其他内容」下。

### 其他规则

- 换句或关闭面板时，取消正在生成的回答，服务器同时停止读取上游。
- 超时：30 秒内无任何输出，或总时长超过 2 分钟。
- 同时进行的模型请求最多 3 个，超出的排队。
- 登录过期时跳到登录页，与现有页面一致。

## 7. 测试

### 样例文章

按实测到的结构制作样例：单页、3 页、带小标题、带视频、杂志类，以及一份去掉正文数据的「改版」页面。正文换成自写的日语句子，不把新闻原文放进仓库。自动测试不访问真实雅虎，由本机假雅虎服务返回样例。

### 服务端测试（Python `unittest`）

- 抓取：话题链接到文章链接；多页按顺序合并；图片与说明位置正确；视频和未知元素有提示。
- 地址检查：拒绝 `news.yahoo.co.jp.evil.com`、跳转到外站、`http://127.0.0.1` 等。
- 切句分词：引号内不切；词典形、读音、词性正确；标点、数字不可点。
- 存储：7 天与 30 天过期；超过 300 MB 先删最早的文章。
- XML 解析：回复被切成碎片、在标签中间断开时能拼接；缺 `<selection>`、标签写错、标签外多出文字时，能解析的部分照常输出。
- 接口：未登录被拒；非同源 POST 被拒；模型请求最多 3 个；换句后上一个请求被取消。
- Caddy：流式接口经过 Caddy 后逐段到达。

### 分环节报错（模拟故障）

真实模型无法按要求制造故障，这一组用模拟：雅虎 503、第 3 页超时、分词组件缺失、qoder2api-hub 连不上、返回 10605、模型下线、中途断开、30 秒无输出。检查报出的环节、位置、原因和请求编号。

### 真实模型测试

通过本机 qoder2api-hub 调用页头选定的模型，单独作为一组运行（会消耗额度），在修改提示词和上线前执行：

- 查词：`<gloss><meaning>` 存在且符合长度要求，助词也能给出功能说明。
- 句子分析：XML 能完整解析；只选整句时没有 `<selection>`，选中部分时有；必需标签齐全；`<level>` 都在 N5–N1 之内；相关语法排在最前。
- 流式：各段逐个到达页面，不是最后一次性到达。
- 追问：连续两轮时，第二轮的回答能用到第一轮的上下文。

### 浏览器测试（Playwright WebKit，模拟 iPad 与 iPhone）

点词弹卡、快速连点只显示最后一个；长按选句并打开面板；拖选对齐整词并出现选中部分；其他位置拖动为滚动；iPad 横屏面板在右、竖屏和 iPhone 从底部弹出；连续追问与换句清空；页头切换模型及模型下线提示；进行中显示环节，报错显示一行并可展开。
