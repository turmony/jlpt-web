# JLPT 网站部署与智能体练习设计

记录日期：2026-10-10。

本文整理本次讨论最终确认的需求与设计。它是后续实现依据；写入本文不代表网站、后台或部署工具已经完成。

## 1. 目标与部署方式

将当前 `jlpt-web` 项目部署到用户正在使用的东京云服务器，提供两个功能：

1. 语法记忆：沿用现有图片卡片页面。
2. 智能体练习：通过用户选择的本地智能体 CLI 出卷和判卷，用户在网页答题。

目前没有域名，首先使用服务器公网 IP 访问。

采用 Caddy 提供页面及本地图片，并将后台接口转发给应用服务。后台负责登录、任务管理、CLI 调用、作答保存、成果检查和本地 Git 提交。

本次检查时服务器为 Ubuntu 24.04、2 核、约 2 GB 内存，磁盘剩余约 16 GB。当前目录包含 598 张语法卡，引用 960 张图片；对应固定资料提交的图片总计约 564 MiB。上述数字是本次检查记录，后续部署以实际情况为准。

现有 Cloudflare 发布包包含图片代理，普通静态服务器不能执行该代理。服务器部署时需将图片同步到本地，并保持页面引用的图片路径有效。

不增加手动资料更新工具。网站资料固定到部署时选定的版本，初次部署包含必要的图片与目录准备工作。

## 2. 两个仓库的分工

| 内容 | 仓库 |
| --- | --- |
| 语法记忆、智能体输入、提示词预览、答题与成绩页面 | `jlpt-web` |
| 登录、后台 API、任务状态、CLI 适配与成果检查 | `jlpt-web` |
| 网站构建及服务器部署配置 | `jlpt-web` |
| 语法卡、原图、出题与判卷技能、资料校验工具 | `turmony/jlpt-study` |
| 题目、试卷、答案、作答、成绩、题源证据与生成清单 | `turmony/jlpt-study` 的本地工作区 |

学习流程复用 `jlpt-study` 中已有规则与工具。网站后台负责将这些流程接入网页。

用户已明确要求生成资料保存在 `jlpt-study` 仓库内，并在判卷完成后提交本地 Git；不自动推送到 GitHub。因此，生成资料首先保存在该仓库的服务器本地分支中，远端不会自动获得这些提交。

## 3. 本地仓库与长期 worktree

先将 `https://github.com/turmony/jlpt-study` 克隆到服务器，再建立一个长期使用的独立 worktree 和分支。

建议路径与分支名称：

```text
/srv/jlpt/repos/jlpt-study/       原始克隆，用于管理远端与 worktree
/srv/jlpt/worktrees/study/       长期学习工作区
web-study                      长期学习分支
```

路径和分支名称属于实现建议，可以根据服务器目录布局调整。

所有出卷、作答、判卷及对应本地 Git 提交均在长期 worktree 中进行。后台在该目录启动 CLI，使其能够读取项目规则、技能、目标卡片和历史成绩。

worktree 长期保留，支持任务中断恢复和连续学习历史。网站重启不应删除生成文件、作答草稿、任务信息或 CLI 会话关联。

共用工作区内的模型写入任务串行执行，Git 暂存与提交也串行处理，避免任务相互覆盖。暂存仅包含当前已完成练习的相关产物，不将其他未完成练习或无关修改一并提交。

## 4. 网站入口与密码

进入网页后先输入密码，验证通过后才能进入后续功能。

- 使用单一网站密码，保持个人使用场景下的操作简单。
- 密码由服务器验证，以哈希形式保存在服务器本地配置中，不写入仓库。
- 浏览器保存服务器签发的登录凭据，默认有效期为一年。
- 同一浏览器在有效期内再次访问时自动进入。
- 清除浏览器数据、主动退出或凭据到期后重新输入密码。
- 登录配置持久保存，正常重启服务器或应用不会使已有登录立即失效。
- 页面、图片、试卷、成绩及后台接口均受相同登录状态保护。

公网密码入口使用 HTTPS。没有域名时可使用可信 IP 证书；证书申请、续期及 Web 服务器重载属于部署工作，不增加用户日常操作。

## 5. 语法记忆

保留当前语法记忆页面的功能，包括：

- N5–N1 等级和卡号范围选择。
- 接续图与例句图切换、翻卡和大图阅读。
- 阅读位置恢复与相邻快捷区间。
- 手机当天图片缓存及既有容量、过期处理规则。
- 图片下载失败后的重试。

图片由当前服务器提供。迁移到新网站来源后，原 Cloudflare 网站的浏览器阅读位置和缓存不会自动迁移。

## 6. 智能体练习页面

统一操作流程：

```text
选择 CLI → 输入提示词 → 预览最终提示词 → 执行
```

智能体页面不设置任务类型、等级或卡号起止字段，也不要求用户手动选定待判试卷。用户通过自由文本描述需求，模型根据提示词与资料库上下文判断：

- 出卷还是判卷。
- 目标等级、语法范围、题量和题型。
- 需要处理的具体试卷。
- 缺少的信息是否需要用户补充。

题量和题型由用户提示词控制，网页不强制固定题量或题型。提示词未写明的信息按项目现有流程处理，必要时由模型请求补充。

模型能够唯一确定目标试卷时直接处理；无法确定时在页面显示模型的问题，用户继续输入提示词。

预览应展示实际交给 CLI 的完整任务提示词，包括用户输入和应用补充的项目流程约束。执行使用同一预览版本；输入变更后重新预览。各 CLI 内置的系统提示与运行时工具消息不属于网页可完整展示的任务提示词。

答题过程中允许直接查看答案和解析，不设置交卷前隐藏答案的限制。

## 7. CLI 选择与适配

页面提供以下 CLI 选项：

| CLI | 非交互调用方式参考 | 已知情况 |
| --- | --- | --- |
| Codex CLI | `codex exec --json` | 本次服务器检查时已安装 |
| Qoder CLI | `qoder -p --output-format stream-json` | 部署时检查安装与登录情况 |
| Antigravity CLI | `agy -p --output-format stream-json` | 用户确认本机已安装并登录 |

用户确认 GitHub CLI 已安装并登录；它不会因此触发自动推送。

后台应识别 CLI 的可用状态，并给出未安装、需要登录或运行失败等实际信息，不宣称未验证的 CLI 已可用。

三种 CLI 通过适配层接入相同的网页流程，复用相同资料规则与产物检查。CLI 失败时不自动切换到其他执行器。

同一任务保留所选 CLI 的会话关联，支持用户补充提示词后继续处理。会话记录不能直接跨不同 CLI 共用。

## 8. 模型职责与后台职责

模型负责：

- 理解用户提示词并确定操作及目标资料。
- 按 `jlpt-study` 的现有技能执行出卷和判卷。
- 生成项目要求的试卷、答案、成绩等文件。
- 在失败、歧义或信息不足时返回说明与问题。
- 根据用户后续提示词继续处理。

后台负责：

- 启动和管理 CLI 进程，保存任务与会话状态。
- 展示进度、模型返回的信息和实际运行错误。
- 保存用户作答、管理交卷状态。
- 检查实际生成文件及项目要求的校验结果。
- 成果检查通过后推进网页流程。
- 在整套练习判卷成功后精确暂存相关文件并执行一次本地 Git 提交。

成功判定以实际产物和校验结果为依据，不能只依赖 CLI 退出码或模型文字中的“已完成”。后台内部需识别操作及关联产物，但不要求用户填写相应结构化字段。

## 9. 出卷与判卷的成功检查

### 出卷成功

检查以下内容：

1. 生成试卷、对应答案及项目流程要求的题卡、清单和证据文件实际存在。
2. 试卷与答案的题目数量、编号和关联关系一致。
3. 产物符合模型从用户提示词确定的范围、题量和题型。
4. 现有项目要求的来源核实、独立审题、结构及链接校验已经完成，并有对应结果。

检查通过后展示试卷并进入答题。出卷阶段不执行 Git 提交。

机械校验只能检查结构、关联和可验证记录，不能单独证明语法正确或题目具有唯一解；这些判断继续由既有出题流程和独立审题负责。

### 判卷成功

检查以下内容：

1. 报告对应正确的试卷和已交卷作答。
2. 成绩报告及项目要求的解析、统计和作答记录完整。
3. 题号、题量、评分与报告记录内部一致。
4. 作答记录按既有格式追加，保留历史内容，重试不会重复追加。
5. 项目要求的相关校验通过。

检查通过后展示判卷结果，并统一执行本地 Git 提交。若提交本身失败，保留已经通过检查的判卷成果，显示提交错误；重试提交时不重新交卷或重复追加作答记录。

## 10. 失败后的继续对话

当出卷、判卷或成果检查失败，或者模型需要补充信息时：

1. 页面保留并显示模型返回的信息。
2. 若 CLI 启动或运行失败且没有模型回复，显示实际错误。
3. 保留任务上下文、已生成文件和已填写答案。
4. 用户继续输入提示词，预览后发送给同一个 CLI 会话。
5. 后台再次检查实际成果，再决定推进流程还是继续等待用户输入。

失败阶段不提交 Git。重试不会生成第二次正式交卷或重复作答记录。

页面提供任务进度、取消和重试入口。取消时保留可恢复的资料，并清楚显示任务状态，不将取消的任务标记为成功。

## 11. 作答与交卷

- 同一试卷只允许一次正式作答与交卷。
- 作答草稿自动保存，退出网页或刷新后可以继续。
- 中途恢复属于同一次作答，不算重复作答。
- 正式交卷后锁定答案，不能重新作答。
- 判卷失败后允许继续提示或重试判卷，但不重新交卷。
- 后台应防止重复点击、请求重试或多标签页造成重复交卷、重复记录。

完整流程为：

```text
提示词与预览
    ↓
模型出卷 → 后台检查
    ↓ 成功
用户作答 → 正式交卷并锁定
    ↓
模型判卷 → 后台检查
    ↓ 成功
展示成绩 → 一次本地 Git 提交
```

任一模型处理或检查环节未完成时，显示返回信息并等待用户补充提示词。

## 12. Git 提交边界

判卷完成并通过检查后，统一提交整套练习相关资料，包括：

- 题目、试卷、对应答案和生成清单。
- 项目要求保存的采用题源证据。
- 用户已交卷作答。
- 成绩报告及新增作答记录。

出卷、作答中途及失败阶段不提交。现有出题和判卷技能中的提交步骤需要适配网页流程，将提交统一交给后台在上述时点执行。

不执行 `git push`。模型任务也应明确遵守不自行提前提交、不推送的约束。

长期分支中的成功提交形成连续学习历史；是否将其推送或合并由用户以后另行决定。

密码、登录凭据、CLI 认证信息及运行临时文件保存在服务器本地配置或运行目录中，不作为学习资料提交。

## 13. 实现与验收顺序

1. 克隆资料仓库，建立长期 worktree，检查所需 CLI 与登录状态。
2. 准备页面、目录和本地图片，并配置 Caddy 与密码入口。
3. 接入提示词预览、CLI 调用、任务进度及继续对话。
4. 接入试卷展示、答案查看、草稿恢复和一次交卷。
5. 接入出卷／判卷成果检查和判卷后的统一本地 Git 提交。
6. 验证正常流程、失败后继续、取消、重复交卷防护、重启恢复及不推送行为。

验收重点：

- 未输入正确密码时不能进入后续功能。
- 登录后的同一浏览器再次打开网站可直接进入。
- 当前本地图片与目录匹配，语法记忆功能正常。
- CLI 选择和提示词预览有效，执行内容与预览一致。
- 模型能处理自由文本出卷／判卷，并在需要时请求补充。
- 后台根据实际产物检查成功状态。
- 失败后保留资料，用户补充提示词可以继续。
- 作答可恢复，正式交卷后不可重复作答。
- 判卷成功后仅产生预期的本地提交，无远端推送。
